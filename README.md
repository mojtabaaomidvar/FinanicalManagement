# مالی من — مدیریت مالی خانواده (PWA)

اپلیکیشن وب مدیریت مالی خانواده، مختص موبایل (iPhone/Android)، فارسی و راست‌به‌چپ.
نسخه ۴.۰.۰ — **React + TypeScript + Clean Architecture**، داده‌ها روی **Supabase**، ورود با **شماره موبایل + رمز + کد پیامکی (OTP)**، دعوت اعضا با **لینک/QR**.

> **نسخه ۴ = بازنویسی معماری‌شده.** اپ نسخه ۳ (JS خالص) در پوشه `legacy/` نگه داشته شده و همچنان قابل اجراست. منطق دامنه (محاسبات مالی، تقویم جلالی، پارسر پیامک) عیناً به TypeScript منتقل و تست‌شده است.

## ✨ امکانات

- 📱 **ورود با موبایل و رمز** — کد پیامکی (OTP) اختیاری است و از تنظیمات سرور قابل فعال‌سازی است
- 🔓 **ماندگاری ورود** — لاگین تا ۷ روز پس از آخرین استفاده باقی می‌ماند (بدون نیاز به ورود مکرر)
- 📝 **ثبت‌نام ساده** — نام خانواده، نام شما، شماره موبایل و رمز عبور
- 🔗 **دعوت اعضا** — لینک دعوت یا **QR Code** برای اضافه کردن اعضای خانواده (از تنظیمات)
- 💳 **تراکنش‌ها** — ثبت/ویرایش/حذف درآمد و هزینه با ۱۴ دسته‌بندی
- 📅 **تقویم جلالی** — الگوریتم دقیق سال کبیسه (چرخه ۳۳ ساله)
- 📊 **گزارش‌ها** — نمودار حلقه‌ای، ستونی روزانه، روند ۶ ماهه (Canvas خالص)
- 📨 **پیامک بانکی** — چسباندن (Paste) متن پیامک واریز/برداشت؛ پارس خودکار بانک، مبلغ، موجودی و تاریخ
- 🔔 **پیامک‌های ثبت‌نشده** — هنگام باز شدن اپ، مودالی پیامک‌های رسیدگی‌نشده را یکی‌یکی برای ثبت نشان می‌دهد
- 🌙 تم تیره/روشن، بودجه ماهانه، خروجی JSON، نصب به‌عنوان اپ (PWA)
- 💳 **کارت‌ها و حساب‌ها** — شماره کارت، حساب و شبا اعضای خانواده با نمایش ماسک‌شده/کامل + کپی سریع
- ✨ **تب‌بار متحرک** — دکمه خانه مرکزی و محوری با انیمیشن فنری + ترنزیشن نرم بین صفحات

## 🏛 معماری (Clean Architecture)

```
src/
├── app/                    # راه‌اندازی اپ (providers، router، App)
├── domain/                 # منطق دامنه خالص — صفر وابستگی فریم‌ورک
│   ├── auth/               # قوانین احراز هویت، انواع نشست
│   ├── budget/             # قوانین بودجه (سقف/هشدار)
│   ├── category/           # کاتالوگ دسته‌بندی‌ها
│   ├── family/             # انتیتی خانواده/اعضا + اینترفیس مخزن
│   ├── report/             # محاسبات گزارش (موجودی، تجزیه دسته، سری ماهانه)
│   ├── sms/                # انتیتی و قوانین پیامک بانکی
│   └── transaction/        # اعتبارسنجی/مرتب‌سازی تراکنش + اینترفیس مخزن
├── application/            # Use-caseها — orchestration بدون UI
├── infrastructure/         # جزئیات فنی قابل تعویض
│   ├── api/                # httpClient مرکزی (تنها نقطه fetch) + OTP سرورless + هش رمز
│   ├── storage/            # secureStorage (رمزنگاری AES-GCM پیش از ذخیره)
│   └── repositories/       # پیاده‌سازی مخازن (RPCهای Supabase)
├── features/               # فیچرهای UI-محور (auth، transaction-form، sms، invite، …)
├── pages/                  # صفحات کامل (Dashboard، Transactions، Reports، Settings)
├── widgets/                # ترکیب چند فیچر (خلاصه داشبورد، پنل گزارش)
└── shared/                 # UI kit، lib (جلالی، فرمت، پارسر پیامک، QR)، config
```

**قوانین سخت:**

1. `domain/` هیچ importی از React/کتابخانه فریم‌ورک ندارد (فقط TS خالص) — آماده استفاده در React Native
2. هر دسترسی API/storage فقط از طریق Repository (اینترفیس در domain، پیاده‌سازی در infrastructure)
3. UI هرگز مستقیم `infrastructure` را صدا نمی‌زند
4. تمام درخواست‌های شبکه فقط از `httpClient.ts` عبور می‌کنند (HTTPS اجباری)
5. داده حساس (توکن نشست) فقط از طریق `secureStorage` (رمزنگاری AES-GCM با کلید غیرقابل استخراج) ذخیره می‌شود
6. محاسبات مالی در `domain/` متمرکز و با تست واحد پوشش داده شده‌اند

## 🚀 راه‌اندازی

### ۱) ساخت پروژه Supabase

1. به [supabase.com](https://supabase.com) بروید → **New Project**
2. پس از ساخت پروژه، به **SQL Editor** بروید
3. کل محتوای [`supabase/schema.sql`](supabase/schema.sql) را Paste و **Run** کنید
   - جدول‌های `sessions`، `auth_attempts` و توابع RPC امن (CRUD با توکن نشست) ساخته می‌شوند

### ۲) تنظیمات اتصال

فایل `.env.local` را در ریشه پروژه بسازید (نمونه: `.env.example`):

```
VITE_SUPABASE_URL=https://abcd1234.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```

### ۳) فعال‌سازی ارسال پیامک OTP

کد OTP از طریق تابع سرورلس [`api/send-otp.js`](api/send-otp.js) روی Vercel ارسال می‌شود. متغیرهای محیطی:

| متغیر                  | توضیح                                                       |
| ---------------------- | ----------------------------------------------------------- |
| `SUPABASE_URL`         | همان Project URL                                            |
| `SUPABASE_SERVICE_KEY` | کلید `service_role` (محرمانه، فقط سرور)                     |
| `SMS_PROVIDER`         | `kavenegar` یا `ghasedak` یا `smsir`                        |
| `KAVENEGAR_API_KEY`    | کلید سرویس کاوه‌نگار                                        |
| `GHASEDAK_API_KEY`     | کلید سرویس قاصدک                                            |
| `SMSIR_API_KEY`        | کلید سرویس SMS.ir                                           |

> **حالت تست (بدون سرویس پیامک):** اگر `SMS_PROVIDER` تنظیم نشده باشد، کد در پاسخ برمی‌گردد تا در مرورگر نشان داده شود. **قبل از استفاده واقعی حتماً سرویس پیامک را وصل کنید و `dev_mode` را false کنید.**

## 🔄 جریان کار اپ

1. **ثبت‌نام** — نام خانواده + نام شما + شماره موبایل + رمز → ورود (اگر OTP فعال باشد: کد ۶ رقمی پیامکی)
2. **ورود** — شماره موبایل + رمز → ورود
3. **دعوت عضو** — تنظیمات → «ساخت لینک» → لینک یا QR را بفرستید
4. **ثبت تراکنش** — دکمه سبز پایین؛ نوع، مبلغ، دسته، عضو، تاریخ (جلالی)
5. **ورود پیامک** — آیکون پیامک در هدر داشبورد → Paste → پیش‌نمایش → ذخیره
6. **پیامک‌های ثبت‌نشده** — مودال خودکار: **ثبت** / **نادیده** / **بعداً**

## 🔐 نحوه کار ورود (خلاصه فنی)

- شماره موبایل به فرمت استاندارد `09xxxxxxxxx` نرمال می‌شود (ارقام فارسی هم پذیرفته می‌شود)
- رمز عبور با **SHA-256** (کلید = شماره موبایل) هش می‌شود
- **کد OTP به‌صورت پیش‌فرض غیرفعال است** (کلید `otp_enabled` در جدول `app_settings`). در صورت فعال‌سازی: کد ۶ رقمی با اعتبار ۵ دقیقه، حداکثر یک درخواست در ۶۰ ثانیه، و برای ورود/ثبت‌نام/دعوت اجباری است — اعتبارسنجی داخل RPC سرور
- **نشست ماندگار با توکن:** توکن ۶۴ کاراکتری که در کلاینت **رمزنگاری‌شده** (AES-GCM) نگه داشته می‌شود — ۷ روز پس از آخرین استفاده منقضی می‌شود؛ هر بار باز کردن اپ اعتبار آن تمدید می‌گردد (۷ روز عدم فعالیت = ورود مجدد)
- **RLS کاملاً بسته:** هیچ جدولی مستقیماً از کلاینت قابل خواندن/نوشتن نیست؛ همه دسترسی‌ها از طریق RPC با `security definer`
- **ضد brute-force:** پس از ۱۰ تلاش ناموفق، شماره ۱۵ دقیقه قفل می‌شود
- **ذخیره‌سازی امن:** توکن نشست با کلید غیرقابل استخراج WebCrypto رمزنگاری و در IndexedDB ذخیره می‌شود

## 🗄 دیتابیس (Supabase)

| جدول             | توضیح                                                         |
| ---------------- | ------------------------------------------------------------- |
| `families`       | خانواده‌ها + تنظیمات (بودجه، واحد، تم)                        |
| `members`        | اعضا — شماره موبایل یکتا + هش رمز + نقش (owner / member)      |
| `transactions`   | تراکنش‌ها — تاریخ میلادی ذخیره، جلالی نمایش                   |
| `sms_messages`   | پیامک‌های بانکی — وضعیت: pending / recorded / ignored         |
| `otp_codes`      | کدهای یک‌بار مصرف ورود — انقضا ۵ دقیقه (فقط وقتی OTP فعال است) |
| `sessions`       | نشست‌های ورود — توکن ۶۴ کاراکتری، انقضا ۷ روز پس از آخرین استفاده |
| `auth_attempts`  | تلاش‌های ورود — قفل ضد brute-force (۱۰ تلاش / ۱۵ دقیقه)       |
| `family_invites` | دعوت‌نامه‌ها — توکن + اعتبار ۳۰ روز                           |
| `accounts`       | کارت‌ها/حساب‌های بانکی — کارت ۱۶رقمی، حساب، شبا (با اعتبارسنجی سرور) |
| `app_settings`   | تنظیمات سراسری — `dev_mode` (تست بدون پیامک) و `otp_enabled` (فعال‌سازی ورود دو مرحله‌ای) |
