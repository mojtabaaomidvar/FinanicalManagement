# خانه یار — دستیار مالی خانواده (PWA)

دستیار مالی خانواده — همراه مطمئن خانواده در مسیر آرامش مالی، مختص موبایل (iPhone/Android)، فارسی و راست‌به‌چپ.
نسخه ۴.۰.۰ — **React + TypeScript + Clean Architecture**، داده‌ها روی **بک‌اند اختصاصی (FastAPI + PostgreSQL)**، ورود با **شماره موبایل + رمز + کد پیامکی (OTP)**، دعوت اعضا با **لینک/QR**.

> **نسخه ۴ = بازنویسی معماری‌شده.** نرم‌افزار نسخه ۳ (JS خالص) در پوشه `legacy/` نگه داشته شده و همچنان قابل اجراست. منطق دامنه (محاسبات مالی، تقویم جلالی، پارسر پیامک) عیناً به TypeScript منتقل و تست‌شده است.

> **🔄 وضعیت مهاجرت (فاز ۹ انجام شد):** فرانت‌اند از Supabase جدا و به بک‌اند اختصاصی وصل شده است — همهٔ درخواست‌ها از یک `RestClient` واحد و مبدأ `VITE_API_URL` (پیشوند `/api/v1`) عبور می‌کنند. لایهٔ قدیمی Supabase/سرورلس (`httpClient`، `apiBase`، `supabase`) بازنشسته شده (حذف نشده). مستند کامل بک‌اند و اندپوینت‌ها در [`backend/README.md`](backend/README.md) است. **در حال انجام:** دپلوی بک‌اند و مهاجرت داده (فاز ۱۰) و چرخش کلیدها (فاز ۱). بخش‌های Supabase زیر تا تکمیل آن فازها به‌عنوان مرجع تاریخی نگه داشته شده‌اند.

## ✨ امکانات

- 📱 **ورود با موبایل و رمز** — کد پیامکی (OTP) اختیاری است و از تنظیمات سرور قابل فعال‌سازی است
- 🔓 **ماندگاری ورود** — لاگین تا ۷ روز پس از آخرین استفاده باقی می‌ماند (بدون نیاز به ورود مکرر)
- 📝 **ثبت‌نام ساده** — نام خانواده، نام شما، شماره موبایل و رمز عبور
- 🔗 **دعوت اعضا** — لینک دعوت یا **QR Code** برای اضافه کردن اعضای خانواده (از تنظیمات)
- 💳 **تراکنش‌ها** — ثبت/ویرایش/حذف درآمد و هزینه با ۱۴ دسته‌بندی
- 📅 **تقویم جلالی** — الگوریتم دقیق سال کبیسه (چرخه ۳۳ ساله)
- 📊 **گزارش‌ها** — نمودار حلقه‌ای، ستونی روزانه، روند ۶ ماهه (Canvas خالص)
- 📨 **پیامک بانکی** — چسباندن (Paste) متن پیامک واریز/برداشت؛ پارس خودکار بانک، مبلغ، موجودی و تاریخ
- 🤖 **پیامک خودکار (اندروید)** — با یک نرم‌افزار فوروارد (Tasker/MacroDroid/SMS Forwarder)، پیامک‌های بانکی بدون کپی خودکار وارد نرم‌افزار می‌شوند (آیفون به‌دلیل محدودیت اپل پشتیبانی نمی‌شود)
- 🔔 **پیامک‌های ثبت‌نشده** — هنگام باز شدن نرم‌افزار، مودالی پیامک‌های رسیدگی‌نشده را یکی‌یکی برای ثبت نشان می‌دهد
- 🌙 تم تیره/روشن، بودجه ماهانه، خروجی JSON، نصب به‌عنوان نرم‌افزار (PWA)
- 💳 **کارت‌ها و حساب‌ها** — شماره کارت اعضای خانواده با نمایش ماسک‌شده/کامل + کپی سریع
- ✨ **تب‌بار متحرک** — دکمه خانه مرکزی و محوری با انیمیشن فنری + ترنزیشن نرم بین صفحات

## 🏛 معماری (Clean Architecture)

```
src/
├── app/                    # راه‌اندازی نرم‌افزار (providers، router، App)
├── domain/                 # منطق دامنه خالص — صفر وابستگی فریم‌ورک
│   ├── auth/               # قوانین احراز هویت، انواع نشست
│   ├── budget/             # قوانین بودجه (سقف/هشدار)
│   ├── category/           # کاتالوگ دسته‌بندی‌ها
│   ├── family/             # انتیتی خانواده/اعضا + اینترفیس مخزن
│   ├── report/             # محاسبات گزارش (موجودی، تجزیه دسته، سری ماهانه)
│   ├── sms/                # انتیتی و قوانین پیامک بانکی
│   └── transaction/        # اعتبارسنجی/مرتب‌سازی تراکنش + اینترفیس مخزن
├── application/            # Use-caseها — orchestration بدون UI
├── infrastructure/         # جزئیات فنی قابل تعویض
│   ├── api/                # restClient مرکزی (تنها نقطه fetch به بک‌اند اختصاصی) + نگاشت خطا
│   ├── storage/            # secureStorage (رمزنگاری AES-GCM پیش از ذخیره)
│   └── repositories/       # پیاده‌سازی مخازن (REST به /api/v1)
├── features/               # فیچرهای UI-محور (auth، transaction-form، sms، invite، …)
├── pages/                  # صفحات کامل (Dashboard، Transactions، Reports، Settings)
├── widgets/                # ترکیب چند فیچر (خلاصه داشبورد، پنل گزارش)
└── shared/                 # UI kit، lib (جلالی، فرمت، پارسر پیامک، QR)، config
```

**قوانین سخت:**

1. `domain/` هیچ importی از React/کتابخانه فریم‌ورک ندارد (فقط TS خالص) — آماده استفاده در React Native
2. هر دسترسی API/storage فقط از طریق Repository (اینترفیس در domain، پیاده‌سازی در infrastructure)
3. UI هرگز مستقیم `infrastructure` را صدا نمی‌زند
4. تمام درخواست‌های شبکه فقط از `restClient.ts` عبور می‌کنند (HTTPS اجباری)
5. داده حساس (توکن نشست) فقط از طریق `secureStorage` (رمزنگاری AES-GCM با کلید غیرقابل استخراج) ذخیره می‌شود
6. محاسبات مالی در `domain/` متمرکز و با تست واحد پوشش داده شده‌اند

## 🚀 راه‌اندازی

### ۱) ساخت پروژه Supabase _(مرجع تاریخی — با تکمیل مهاجرت جای خود را به بک‌اند اختصاصی [`backend/`](backend/README.md) می‌دهد)_

1. به [supabase.com](https://supabase.com) بروید → **New Project**
2. پس از ساخت پروژه، به **SQL Editor** بروید
3. کل محتوای [`supabase/schema.sql`](supabase/schema.sql) را Paste و **Run** کنید
   - جدول‌های `sessions`، `auth_attempts` و توابع RPC امن (CRUD با توکن نشست) ساخته می‌شوند

### ۲) تنظیمات اتصال

فایل `.env.local` را در ریشه پروژه بسازید و مبدأ بک‌اند اختصاصی را ست کنید (بدون پیشوند `/api/v1` — خود کلاینت آن را اضافه می‌کند):

```
VITE_API_URL=https://api.example.com
```

> اگر ست نشود، مبدأ نسبی همان دامنه استفاده می‌شود (برای وب هم‌دامنه با بک‌اند کافی است؛ نرم‌افزار نیتیو به آدرس مطلق نیاز دارد).
>
> **بازنشسته (فاز ۹):** `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` دیگر خوانده نمی‌شوند و باید از محیط حذف و کلیدها چرخانده شوند (فاز ۱).

### ۳) فعال‌سازی ارسال پیامک OTP

کد OTP از خود بک‌اند اختصاصی ارسال می‌شود. متغیرها در فایل `backend/deploy/.env` روی سرور ست می‌شوند (راهنما: [`backend/deploy/README-VPS.md`](backend/deploy/README-VPS.md)):

| متغیر          | توضیح                                                    |
| -------------- | -------------------------------------------------------- |
| `SMS_PROVIDER` | فعلاً تنها درگاه شناخته‌شده `kavenegar` است (خالی = همان)  |
| `SMS_API_KEY`  | کلید سرویس کاوه‌نگار                                      |
| `SMS_SENDER`   | شماره/عنوان فرستنده (اختیاری)                             |

> **حالت تست (بدون سرویس پیامک):** اگر `SMS_PROVIDER` تنظیم نشده باشد، کد در پاسخ برمی‌گردد تا در مرورگر نشان داده شود. **قبل از استفاده واقعی حتماً سرویس پیامک را وصل کنید و `otp_enabled` را در تنظیمات سرور روشن کنید.**

### ۳.۵) پیامک خودکار (اختیاری — اندروید)

وب‌هوک پل پیامک روی خود بک‌اند اجرا می‌شود (`POST /api/v1/sms/bridge-ingest` با توکن پل) — تنظیم اضافه‌ای نیاز نیست.

**راه‌اندازی:** تنظیمات نرم‌افزار → «پیامک خودکار (اندروید)» → ساخت کلید اتصال؛ سپس در نرم‌افزار فوروارد (Tasker / MacroDroid / SMS Forwarder) قانون «دریافت پیامک ← POST به آدرس اتصال با بدنه JSON» بسازید (بدنه آماده در همان صفحه قابل کپی است). پیامک‌ها با وضعیت «ثبت‌نشده» وارد نرم‌افزار می‌شوند و در باز شدن بعدی برای ثبت پیشنهاد می‌شوند.

## 🤖 نسخه اندروید (Capacitor)

نرم‌افزار وب همان‌طور که هست داخل یک نرم‌افزار نیتیو اندروید بسته می‌شود — بدون بازنویسی:

```bash
npm run cap:sync     # بیلد وب + کپی به پروژه اندروید
npm run cap:android  # باز کردن پروژه در Android Studio
```

- **پروژه نیتیو** در پوشه `android/` (appId: `ir.khaneyar.app`، نام: «خانه یار»)
- **API**: در نرم‌افزار نیتیو درخواست‌ها به `VITE_API_URL` (بک‌اند اختصاصی) از طریق `RestClient` می‌روند؛ در مرورگر اگر ست نشود، مبدأ نسبی همان دامنه. منطق دو-مسیره (مستقیم/پروکسی سوپابیس) در فاز ۹ بازنشسته شد.
- **دسترسی پیامک**: `RECEIVE_SMS`/`READ_SMS` در مانیفست تعریف شده؛ پلاگین نیتیو خواندن پیامک بانکی (پیش‌زمینه) پیاده شده و متن خام را به `POST /sms/ingest` می‌فرستد. وب/iOS بی‌صدا رد می‌شود و پل فورواردر فالبک است.
- **PWA/ServiceWorker** در نرم‌افزار نیتیو غیرفعال است (به‌روزرسانی از استور/APK)

### ساخت APK (یک‌بار برای همیشه)

1. [Android Studio](https://developer.android.com/studio) را نصب کنید (شامل SDK و JDK)
2. `npm run cap:android` → پروژه باز می‌شود
3. **Build ← Build Bundle(s)/APK(s) ← Build APK(s)** → خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`
4. برای نسخه انتشار: **Build ← Generate Signed Bundle/APK** (به keystore امضا نیاز دارد)
5. APK را مستقیم توزیع کنید یا در کافه‌بازار/مایکت منتشر کنید

> تغییرات وب: `npm run cap:sync` و بعد دوباره Build. فایل‌های داخل `android/app/src/main/assets/public` ساخته‌شده‌اند و کامیت نمی‌شوند.
>
> iOS: نیاز به مک + Xcode + اکانت Apple Developer دارد (فعلاً از PWA «Add to Home Screen» استفاده کنید).

## 🔄 جریان کار نرم‌افزار

1. **ثبت‌نام** — نام خانواده + نام شما + شماره موبایل + رمز → ورود (اگر OTP فعال باشد: کد ۶ رقمی پیامکی)
2. **ورود** — شماره موبایل + رمز → ورود
3. **دعوت عضو** — تنظیمات → «ساخت لینک» → لینک یا QR را بفرستید
4. **ثبت تراکنش** — دکمه سبز پایین؛ نوع، مبلغ، دسته، عضو، تاریخ (جلالی)
5. **ورود پیامک** — آیکون پیامک در هدر داشبورد → Paste → پیش‌نمایش → ذخیره
6. **پیامک‌های ثبت‌نشده** — مودال خودکار: **ثبت** / **نادیده** / **بعداً**

## 🔐 نحوه کار ورود (خلاصه فنی)

- شماره موبایل به فرمت استاندارد `09xxxxxxxxx` نرمال می‌شود (ارقام فارسی هم پذیرفته می‌شود)
- رمز عبور با **SHA-256** (کلید = شماره موبایل) هش می‌شود
- **کد OTP به‌صورت پیش‌فرض غیرفعال است** (کلید `otp_enabled` در جدول `app_settings`). در صورت فعال‌سازی: کد ۶ رقمی با اعتبار ۵ دقیقه، حداکثر یک درخواست در ۶۰ ثانیه، و برای ورود/ثبت‌نام/دعوت اجباری است — اعتبارسنجی داخل RPC سرور
- **نشست ماندگار با توکن:** توکن ۶۴ کاراکتری که در کلاینت **رمزنگاری‌شده** (AES-GCM) نگه داشته می‌شود — ۷ روز پس از آخرین استفاده منقضی می‌شود؛ هر بار باز کردن نرم‌افزار اعتبار آن تمدید می‌گردد (۷ روز عدم فعالیت = ورود مجدد)
- **RLS کاملاً بسته:** هیچ جدولی مستقیماً از کلاینت قابل خواندن/نوشتن نیست؛ همه دسترسی‌ها از طریق RPC با `security definer`
- **ضد brute-force:** پس از ۱۰ تلاش ناموفق، شماره ۱۵ دقیقه قفل می‌شود
- **ذخیره‌سازی امن:** توکن نشست با کلید غیرقابل استخراج WebCrypto رمزنگاری و در IndexedDB ذخیره می‌شود

## 🗄 دیتابیس (Supabase)

| جدول             | توضیح                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------- |
| `families`       | خانواده‌ها + تنظیمات (بودجه، واحد، تم)                                                    |
| `members`        | اعضا — شماره موبایل یکتا + هش رمز + نقش (owner / member)                                  |
| `transactions`   | تراکنش‌ها — تاریخ میلادی ذخیره، جلالی نمایش                                               |
| `sms_messages`   | پیامک‌های بانکی — وضعیت: pending / recorded / ignored                                     |
| `otp_codes`      | کدهای یک‌بار مصرف ورود — انقضا ۵ دقیقه (فقط وقتی OTP فعال است)                            |
| `sessions`       | نشست‌های ورود — توکن ۶۴ کاراکتری، انقضا ۷ روز پس از آخرین استفاده                         |
| `auth_attempts`  | تلاش‌های ورود — قفل ضد brute-force (۱۰ تلاش / ۱۵ دقیقه)                                   |
| `family_invites` | دعوت‌نامه‌ها — توکن + اعتبار ۳۰ روز                                                       |
| `accounts`       | کارت‌ها/حساب‌های بانکی و کیف‌پول‌ها — کارت ۱۶رقمی + موجودی اولیه                          |
| `sms_bridges`    | پل پیامک — کلید اتصال نرم‌افزار فوروادر اندروید برای هر عضو                               |
| `app_settings`   | تنظیمات سراسری — `dev_mode` (تست بدون پیامک) و `otp_enabled` (فعال‌سازی ورود دو مرحله‌ای) |

## 🛠 تکنولوژی

- **React 18 + TypeScript + Vite** — بدون فریم‌ورک UI اضافه (HTML/CSS موجود)
- Clean Architecture (domain / application / infrastructure / features)
- بک‌اند اختصاصی: **FastAPI + PostgreSQL** (احراز با توکن Bearer، RLS خانواده، پارسر پیامک و آپلود فایل سمت سرور) — کلاینت با `fetch` خالص از `RestClient` وصل می‌شود
- ارسال پیامک OTP و وب‌هوک پل پیامک روی همان بک‌اند (Vercel Serverless به‌طور کامل حذف شد)
- qrcode-generator (vendored) + Canvas 2D با پشتیبانی Retina
- Vazirmatn (فونت فارسی) + iOS HIG الگوهای طراحی
- vitest برای تست محاسبات مالی
