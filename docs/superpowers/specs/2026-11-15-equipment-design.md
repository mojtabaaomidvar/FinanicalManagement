# وسایل خانه و سرویس‌های دوره‌ای — نسخهٔ اول

کاربر پس از تکمیل برنامهٔ غذایی، پیشنهاد ثبت وسایل، تاریخ خرید و گارانتی، اتصال به سند موجود، موعد سرویس و یادآور و ثبت سابقهٔ سرویس را پذیرفت. این مرحله یک ماژول تازه در معماری موجود است و ظاهر، نشست، اعضا، اسناد، کارهای خانه و هستهٔ اعلان فعلی را به کار می‌گیرد.

## دامنهٔ استفاده

نام وسیله لازم است؛ برند، مدل، تاریخ خرید، پایان گارانتی، موعد سرویس بعدی، سند گارانتی و کار مرتبط اختیاری‌اند. تاریخ‌ها در رابط شمسی و در API روز میلادی‌اند. فهرست جست‌وجو و وضعیت سرویس نزدیک/گذشته و گارانتی دارد. جزئیات وسیله اطلاعات و تاریخچهٔ سرویس را نشان می‌دهد. مدیر اصلی، مدیر دوم و سازنده اجازهٔ ویرایش، حذف و ثبت سرویس دارند؛ همهٔ اعضای فعال خانواده مشاهده و ثبت وسیلهٔ تازه دارند.

ثبت سرویس، تاریخ انجام و شرح کوتاه لازم دارد و تاریخ سرویس بعدی اختیاری است. تاریخ انجام از امروز تهران جلوتر نیست و موعد بعدی، در صورت ثبت، بعد از انجام است. پس از ثبت موفق، موعد وسیله با مقدار انتخاب‌شده جایگزین می‌شود؛ موعد خالی یادآور سرویس را متوقف می‌کند. تاریخچه افزایشی است و در این نسخه ویرایش/حذف مستقل ندارد. حذف وسیله با تأیید روشن، سابقهٔ همان وسیله را هم حذف می‌کند؛ سند و کار مرتبط حذف یا تکمیل نمی‌شوند.

دورهٔ خودکار، هزینه، اطلاعات تعمیرکار، تراکنش مالی، خودرو و آفلاین در نسخهٔ اول نیستند. تعیین موعد بعدی هنگام ثبت سرویس انجام می‌شود. سند فقط از اسناد مشترک و قابل‌مشاهدهٔ همان خانواده انتخاب می‌شود؛ سند خصوصی قابل اتصال نیست. اگر سند حذف یا خصوصی شود، اتصال نباید دسترسی تازه‌ای ایجاد کند. دریافت و پیش‌نمایش سند از مسیر مجاز اسناد موجود با بررسی تازهٔ سرور انجام می‌شود. کار فقط به کار موجود همان خانواده وصل می‌شود؛ کار و ثبت سرویس دو عمل صریح مستقل‌اند.

## قرارداد داده و API

مهاجرت افزایشی `0018`، جدول‌های `home_equipment` و `maintenance_records` را با RLS و FORCE RLS اضافه می‌کند. شناسهٔ خانواده و سازنده از نشست سرور گرفته می‌شوند. نسخهٔ وسیله در ویرایش، حذف و ثبت سرویس لازم است. ارتباط سابقه و وسیله و ارتباط‌های سند/کار باید خانواده را در دیتابیس نیز حفظ کنند. حذف سند/کار فقط ارجاع اختیاری مربوط را خالی می‌کند. حذف عضو، وسیله و سابقهٔ مشترک را حفظ و ارجاع سازنده را خالی می‌کند؛ حذف خانواده داده‌های متعلق به همان خانواده را پاک می‌کند.

`Equipment` در فرانت‌اند:

```ts
interface Equipment {
  id: string; title: string; brand: string | null; model: string | null;
  purchaseDate: string | null; warrantyUntil: string | null;
  warrantyDocumentId: string | null; serviceTaskId: string | null;
  serviceDueDate: string | null; serviceReminderEnabled: boolean;
  createdBy: string | null; revision: number; createdAt: string; updatedAt: string;
  canEdit: boolean; canDelete: boolean;
}
interface MaintenanceRecord {
  id: string; equipmentId: string; performedOn: string; description: string;
  nextDueDate: string | null; createdBy: string | null; createdAt: string;
}
```

- `GET /equipment` و `POST /equipment`: فهرست و ثبت وسیله.
- `PATCH /equipment/{id}`: بدنهٔ کامل اطلاعات و `base_revision`.
- `DELETE /equipment/{id}?base_revision=...`: حذف وسیله و سابقهٔ وابسته.
- `GET /equipment/{id}/services`: تاریخچه، جدیدترین تاریخ انجام نخست.
- `POST /equipment/{id}/services`: `operation_id` UUID، `base_revision`، `performed_on`، `description` و `next_due_date`. پاسخ `{equipment, record, replayed}` است.

نام‌ها در API snake_case و در فرانت camelCase‌اند. سقف وسیلهٔ خانواده ۲۰۰، نام ۱۲۰ نویسه، برند و مدل ۸۰، شرح سرویس ۱۰۰۰ و تاریخچهٔ هر وسیله ۵۰۰ است. فیلدهای اضافی و تاریخ نامعتبر رد می‌شوند. سرویس و تغییر موعد در یک تراکنش ثبت می‌شوند. شناسهٔ عملیات در تلاش دوبارهٔ بدون تغییر حفظ می‌شود؛ پاسخ گم‌شده یا درخواست هم‌زمان سابقهٔ تکراری نمی‌سازد و تغییر بدنه با همان شناسه رد می‌شود. بازپخش فقط برای همان درخواست‌کننده و با بررسی مجوز فعلی است.

## اتصال به اعلان‌ها

دامنهٔ `equipment` به هستهٔ مشترک اعلان اضافه می‌شود: موعد سرویس روشن و پایان گارانتی هر وسیله، با پیش‌هنگام پیش‌فرض ۷ روز. کلید کلی و کلید دامنه و روزهای پیش‌هنگام از همان تنظیمات اعلان‌اند؛ کلید سرویس هر وسیله نیز در فرم آن است. نوع مرجع اعلان `{kind:"equipment", equipmentId, reason:"service"|"warranty"}` است. اعلان قابل رسیدگی به جزئیات همان وسیله می‌رود. ثبت سرویس موعد قبلی را برمی‌دارد؛ سند گارانتی و یادآور سند مستقل می‌مانند و متن و فایل آن در اعلان وسیله قرار نمی‌گیرد.

این ماژول آنلاین است: داده، فرم و تاریخچه در حافظهٔ نشست‌اند و به IndexedDB، localStorage یا کش Service Worker وارد نمی‌شوند. قطع اتصال، خروج، رد مجوز و تغییر حساب دادهٔ نمایشی و فرم را پاک می‌کند و پاسخ دیررس پذیرفته نمی‌شود. API موفق و خطا `Cache-Control: no-store` دارد. صف و دادهٔ آفلاین موجود دست‌نخورده‌اند.

## مرور امنیتی پیش از پیاده‌سازی

۱. وسیله دادهٔ مشترک خانواده و سابقهٔ نگهداری طبق §۵.۲ دادهٔ حساس است؛ در این نسخهٔ غیرمالی دسترسی سابقه صریحاً برای اعضای فعال همان خانواده است و متن آن فقط آنلاین است.
۲. خانواده و سازنده از سرور تعیین می‌شوند؛ نقش یا خانواده ورودی فرم نیست.
۳. فقط اعضای فعال همان خانواده مشاهده می‌کنند.
۴. هر عضو فعال می‌تواند وسیله بسازد.
۵. سازنده یا مدیر، با نسخهٔ معتبر، وسیله را ویرایش می‌کند.
۶. همان مجوز و نسخه برای حذف و ثبت سرویس لازم است.
۷. هزینه، پزشکی، دادهٔ تعمیرکار و فایل خصوصی در دامنهٔ این مرحله نیست.
۸. پرچم‌های مجازبودن پاسخ صرفاً برای رابط‌اند؛ مجوز در هر عمل روی سرور بررسی می‌شود.
۹. لینک سند فقط مشترک و با مجوز فعلی است؛ سن و مالکیت سند دور زده نمی‌شوند.
۱۰. تغییر شناسهٔ وسیله، سند، کار یا عملیات موجب بررسی مجدد می‌شود.
۱۱. RLS، FORCE RLS و روابط خانواده مرز دیتابیس را حفظ می‌کنند.
۱۲. فیلدهای اضافه و سازنده/خانوادهٔ ارسالی رد می‌شوند.
۱۳. شناسهٔ عملیات و ثبت اتمیک از تاریخچهٔ تکراری جلوگیری می‌کنند.
۱۴. لاگ فقط عمل و شناسه‌هاست؛ عنوان، شرح، فایل و توکن چاپ نمی‌شوند.
۱۵. خروجی گروهی یا نشانی عمومی تازه ساخته نمی‌شود.
۱۶. حذف وسیله سابقهٔ همان وسیله را حذف می‌کند و سند و کار را حفظ می‌کند.

## اعتبارسنجی و تحویل

آزمون PostgreSQL واقعی، عضویت و خانواده، سازنده و مدیر دوم، تعارض نسخه، تاریخ‌ها، لینک خصوصی/خانوادهٔ دیگر، حذف سند/کار/عضو/خانواده، ثبت سرویس اتمیک، تکرار و رقابت هم‌زمان را پوشش می‌دهد. آزمون قواعد فرانت، موعد و گارانتی و تنظیم اعلان را می‌سنجد. مرورگر، فرم شمسی و موبایل، ثبت و ویرایش وسیله، سند/کار مرتبط، سرویس و سابقه و موعد جدید، پاسخ گم‌شده بدون تکرار، مجوز عضو دیگر، اعلان و قطع اتصال را از HTTP واقعی بررسی می‌کند. محیط تست دستی حفظ و نسخهٔ تازه برای آزمون روشن می‌شود؛ انتشار تولید در این مرحله انجام نمی‌شود.
