# بستهٔ ارتقای خانه‌یار — ۲۰۲۶-۱۱-۱۷

این بسته برای انتقال امکانات تکمیل‌شدهٔ محیط محلی به نسخهٔ اصلی است: خرید و انبار آفلاین، کارهای خانه و عکس انجام کار، اسناد، برنامهٔ غذایی، وسایل، خودرو، اهداف شخصی، برنامه‌های خانوادگی، فرزندان، حیوانات خانگی، تقویم و تولدها، صفحهٔ خانه و چیدمان شخصی آن. نوشته‌ها و تغییرهای اعمال‌شده از ویرایشگر محلی نیز در منبع برنامه باقی می‌مانند. خود ویرایشگر و داده‌های ساختگی پیش‌نمایش وارد خروجی PWA نمی‌شوند.

با بازکردن یک دسته در خانه، دستهٔ قبلی بسته می‌شود. حالت قدیمی چند دستهٔ باز به آخرین دستهٔ شناخته‌شده تبدیل می‌شود. انتقال با لمس، ماوس و صفحه‌کلید نیز این رفتار را حفظ می‌کند؛ پس از انتقال سریع به دستهٔ بسته، فوکوس روی عنوان همان دسته می‌ماند.

## نصب روی سرور فعلی

دسترسی SSH به `193.138.77.239:22` همچنان timeout شد؛ کاربر نصب از کنسول VNC پارس‌پک را انتخاب کرده است. انتشار کد و بسته، به‌تنهایی تأیید نصب روی سرور نیست.

**نصب نسخهٔ `r1` تکمیل و تأیید شد.** تصویر بعدی VNC پیام `RELEASE INSTALLED: household-2026-11-17-r1`، شروع کانتینر API، موفقیت بررسی nginx و ارتقای دیتابیس به `0024` با حفظ RLS و اعطای مجوز برنامه را نشان داد. مسیر بکاپ چاپ‌شده `/var/backups/khaneyar/releases/20261117-101617` است. مسیر دقیق منبع استخراج‌شده در خروجی نصب و `docker-compose.release.json` همان سرور موجود است و باید حفظ شود.

بررسی مستقل دامنه‌های عمومی در ۲۰۲۶-۱۱-۱۷، ساعت ۱۱:۰۷ UTC، موفق بود: هر ۱۴ فایل PWA شامل HTML، JavaScript، CSS، manifest، service worker، فونت و آیکون‌ها پاسخ ۲۰۰ دادند و SHA-256 آن‌ها با بستهٔ تأییدشده دقیقاً برابر بود. تنظیمات احراز هویت API پاسخ ۲۰۰ داد و هر ۱۰ مسیر واقعی امکانات جدید بدون نشست با ۴۰۱ رد شد. برنامهٔ غذایی از مسیر `/meals/dishes` بررسی شد. حساب، نشست یا داده‌ای در تولید ساخته نشد.

دو خطای `curl` ابتدای شروع کانتینر، مربوط به تلاش‌های اولیهٔ حلقهٔ آمادگی بودند؛ نصب‌کننده بعد از پاسخ موفق ادامه داد و بررسی بیرونی نیز سلامت را تأیید کرد. گزارش عمومی `server-verification.json` به انتشار `r1` پیوست می‌شود. مقدار `installed_on_server:false` در `validation.json` داخل آرشیو، وضعیت هنگام ساخت بسته است؛ تأیید پس از نصب در گزارش مستقل ثبت می‌شود.

بستهٔ عمومی اصلاح‌شده با برچسب `household-2026-11-17-r1` شامل منبع همان commit و ساخت PWA با API اصلی است. دیتابیس محلی، نشست‌ها، فایل‌های آپلودی، کلیدها، پیش‌نویس‌های محلی و نمونهٔ طراحی در بسته نیستند. APK تازه لازم نیست؛ نسخهٔ موجود از PWA اصلی استفاده می‌کند.

`install.sh` آرشیو را با SHA-256 بررسی و در پوشهٔ مستقل زیر `/opt` استخراج می‌کند. نصب‌کننده ابتدا تصویر API را می‌سازد؛ شکست دریافت وابستگی‌ها در همین گام، پیش از توقف API یا تغییر دیتابیس رخ می‌دهد. ساخت محلی تصویر Docker در این بررسی به‌دلیل timeout دریافت metadata تصویر رسمی Python از Docker Hub تکمیل نشد.

پس از ساخت تصویر، نصب‌کننده API را کوتاه متوقف می‌کند و از دیتابیس و آپلودها بکاپ می‌گیرد. تنظیمات `.env`، نسخهٔ وب و کانفیگ nginx نیز در پوشهٔ خصوصی `/var/backups/khaneyar/releases/` حفظ می‌شوند. دیتابیس موجود با مهاجرت‌های افزایشی `0012` تا `0024` ارتقا می‌یابد؛ هیچ دادهٔ آزمایشی به سرور منتقل نمی‌شود و بازگردانی یا کاهش نسخهٔ دیتابیس خودکار انجام نمی‌شود.

نقش برنامه باید `NOSUPERUSER` و `NOBYPASSRLS` باشد. DDL با نقش مدیریت همان دیتابیس اجرا و مجوز جدول‌های تازه به نقش برنامه داده می‌شود؛ RLS و FORCE RLS حفظ می‌شوند. کلید موجود اسناد تغییر نمی‌کند. اگر کلید هنوز تنظیم نشده باشد، فقط برای دیتابیس فاقد سند و هدف رمزنگاری‌شده، کلید جدید ساخته و در `.env` همان سرور حفظ می‌شود.

منبع سرور در checkout موجود بازنویسی نمی‌شود؛ تصویر از منبع بستهٔ استخراج‌شده ساخته می‌شود. فایل مکمل `docker-compose.release.json` تصویر و مسیر ساخت را تعیین می‌کند و `COMPOSE_FILE` آن را در کنار کانفیگ‌های موجود فعال می‌کند. سایر تنظیمات سرور حفظ می‌شوند. مسیر منبع چاپ‌شده پس از نصب برای ساخت‌های بعدی باید باقی بماند.

نصب‌کننده پس از بررسی API، نسخهٔ وب را جایگزین می‌کند، سقف آپلود موجود nginx را به `12m` می‌رساند و صفحهٔ دریافت را تازه می‌کند. APK و فایل‌های آپلودی فعلی حفظ می‌شوند. در شکست نصب، نسخهٔ قبلی API و فایل‌های وب برگردانده می‌شوند؛ پس از آغاز مهاجرت، کلید رمزنگاری حفظ می‌شود تا تلاش دوباره آن را عوض نکند.

نتیجهٔ نصب باید شامل `RELEASE INSTALLED: household-2026-11-17-r1` باشد. سپس HTML، دارایی‌ها، service worker و API از دامنهٔ عمومی بررسی می‌شوند. نتیجهٔ واقعی سرور پس از اجرای کاربر جداگانه ثبت می‌شود.

## اصلاح پایان خط بستهٔ نخست

تصویر VNC کاربر، دریافت کامل آرشیو و SHA-256 موفق را تأیید کرد؛ اجرای نصب‌کننده در خط سوم با `invalid option name` متوقف شد. بررسی بایت‌های خود آرشیو نشان داد `git archive` با `core.autocrlf=true` اسکریپت‌های shell را به CRLF تبدیل کرده بود. فایل تولیدشدهٔ `release-tag.txt` نیز CRLF داشت و در مرحلهٔ بعد نام تصویر Docker را خراب می‌کرد. این شکست پیش از ساخت تصویر، توقف API یا تغییر دیتابیس رخ داد.

نسخهٔ `r1` با غیرفعال‌کردن تبدیل پایان خط هنگام archive و نوشتن صریح LF در فایل برچسب تولید می‌شود. `.gitattributes` پایان خط اسکریپت‌های shell آینده را نیز LF نگه می‌دارد. `scripts/check-release-archive.py` بایت‌های shell و برچسب را در خود آرشیو و رسیدن اسکریپت بسته‌بندی‌شده به بررسی آرگومان الزامی، پیش از هر عملیات سرور، می‌سنجد. بستهٔ نخست در این بررسی رد شد. کد برنامه و ساخت PWA در این اصلاح تغییر نکرده‌اند.
