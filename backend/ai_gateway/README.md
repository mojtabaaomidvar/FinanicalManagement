# درگاه خصوصی DeepSeek روی سرور پارس‌پک

مسیر تأییدشده: **برنامه ← سرور پارس‌پک ← API رسمی DeepSeek**.
در محیط تست، بک‌اند محلی ابتدا نشست، خانواده و مجوزهای بخش مرتبط را بررسی می‌کند و متن
پالایش‌شده را به درگاه می‌فرستد. گزارش دستیار نسخهٔ ۲، دادهٔ محدود و مرتبطِ بخش‌های مجاز خانه
را نیز می‌فرستد؛ نه تمام snapshot خانه، شماره‌های حساس، رمزها یا محتوای فایل‌ها.
کلید DeepSeek فقط روی سرور است؛ PWA و APK آن را دریافت نمی‌کنند.
درگاه به دیتابیس، فایل‌ها و نشست کاربران دسترسی ندارد و فقط قراردادهای محدود تحلیل پیامک و
شناخت درخواست و گزارش خانه را می‌پذیرد؛ مقصد، مدل و دستور تحلیل را کاربر برنامه نمی‌تواند
تغییر دهد. آماده‌سازی تأیید، اجرا و استعلام رسید فقط در بک‌اند برنامه انجام می‌شوند، نه درگاه.

مدل پیش‌فرض `deepseek-flash` با JSON و حالت تفکر خاموش است. OpenRouter در مسیر تحلیل جدید
وجود ندارد و خطای DeepSeek باعث تغییر خودکار مدل یا سرویس نمی‌شود. شناسه‌پوشانی، اعتبارسنجی
مبلغ و واحد، پیشنهاد قابل‌ویرایش و تأیید کاربر پیش از ثبت همچنان حفظ شده‌اند. شناسه‌پوشانی
ناشناس‌سازی کامل نیست: سرور و DeepSeek متن پالایش‌شده را پردازش می‌کنند.

## هزینه و محافظت‌های فنی

یک کلید متعلق به صاحب برنامه هزینهٔ همهٔ درخواست‌ها را پرداخت می‌کند. سقف مالی، سهمیهٔ
روزانه یا محدودیت قدیمی ۱۲ تحلیل در ساعت اعمال نمی‌شود. هر تحلیل هزینهٔ API دارد و موجودی
حساب و محدودیت‌های خود DeepSeek همچنان ممکن است باعث خطا شوند.

برای ظرفیت سرویس، احراز هویت، ورودی حداکثر ۲۵۶ کیلوبایت و ۸ پیامک، مهلت محدود، پیش‌فرض
۲۰ درخواست در دقیقه و دو درخواست هم‌زمان باقی می‌مانند؛ این‌ها سقف مالی یا سهمیهٔ روزانه نیستند.
کلید و متن پیامک در خروجی نصب یا لاگ برنامه چاپ نمی‌شوند.

## انتقال درگاه فعال از VNC

این انتقال فقط سرویس مستقل `khaneyar-ai-gateway` را تغییر می‌دهد؛ انتشار کامل برنامهٔ اصلی
و تغییر دیتابیس یا داده‌های دستی جزو آن نیست.

۱. روی رایانهٔ پروژه، `prepare-ai-gateway.bat` را اجرا کنید. بستهٔ کد، checksum و
`vnc-installer.py` در `.local-test/ai-gateway/` ساخته می‌شوند. ساخت بستهٔ انتقال به کلید
DeepSeek در رایانه نیاز ندارد و فایل‌های خصوصی قبلی را دست‌نخورده نگه می‌دارد.

۲. نسخهٔ بررسی‌شده را با `python scripts/publish-ai-gateway.py` منتشر کنید. ابزار، فایل و
آرشیو داخلی را برای کلیدها بررسی می‌کند و پس از دانلود مجدد و مقایسهٔ بایت‌ها، دو دستور کوتاه
را در `vnc-deepseek-download.txt` می‌نویسد. این ابزار فقط کد بدون تنظیمات خصوصی را منتشر می‌کند.

۳. `setup-ai-vnc.bat` را باز کنید. دستور دانلود و اجرا را جداگانه در کنسول root پارس‌پک
وارد کنید. دستور اجرا برای انتقال سرویس فعال چنین است:

```sh
python3 /tmp/ai.py --migrate-deepseek
```

از لینک‌های نصب قبلی یا گزینهٔ قدیمی `--resume-free` استفاده نکنید؛ نسخهٔ جدید آن را نمی‌پذیرد.
اگر کنسول روی `>` مانده، پیش از شروع با Ctrl+C به خط فرمان عادی برگردید.

۴. فقط جلوی `DeepSeek API key (hidden):` کلید **جدید DeepSeek** را وارد کنید. کلید را در
چت، دستور شل یا عکس صفحه نفرستید. اگر ورودی مخفی ممکن نباشد نصب متوقف می‌شود. رمز اختصاصی
درگاه از `.env` موجود خوانده و حفظ می‌شود؛ آن را دوباره وارد نمی‌کنید.

نصب‌کننده هویت سرویس روشن، فایل‌های مدیریت‌شده و عدم اجرای هم‌زمان نصب‌کنندهٔ دیگر را
بررسی می‌کند. نسخهٔ جدید در پوشه و image جدا، بدون دست‌زدن به سرویس فعال، ساخته می‌شود؛
فهرست مدل‌های DeepSeek با کلید بررسی و **یک تحلیل نمونه** اجرا می‌شود. اگر این مرحله شکست
بخورد، سرویس فعلی تغییر نمی‌کند.

پس از موفقیت، کد، `.env`، nginx و شناسهٔ image قبلی در
`/var/backups/khaneyar/ai-gateway/` به‌صورت خصوصی پشتیبان‌گیری می‌شوند. محیط فعال فقط کلید
DeepSeek را نگه می‌دارد؛ کلید قدیمی از محیط فعال حذف می‌شود، نه از پشتیبان‌های بازگردانی.
رمز درگاه و تنظیمات فنی و دستی دیگر حفظ می‌شوند.

نسخهٔ جدید سپس روی همان پورت loopback `5810` و مسیر موجود
`https://api.khaanehyar.ir/ai-gateway` جایگزین می‌شود. سلامت، خطای دقیق احراز هویت و TLS
عمومی بررسی و **یک تحلیل نمونهٔ دوم از HTTPS عمومی** اجرا می‌شود. موفقیت به مبلغ صحیح
۱۰٬۰۰۰ ریال، نوع واریز و source index صحیح نیاز دارد؛ صرف دریافت JSON کافی نیست.

در صورت شکست فعال‌سازی، نسخهٔ قبلی با image قبلی و تنظیمات محفوظ برمی‌گردد. این بازیابی
نصب است، نه fallback درخواست تحلیل. اگر مدیر هم‌زمان فایلی را تغییر داده باشد، بازگردانی
خودکار متوقف می‌شود تا تغییر او بازنویسی نشود؛ مسیر پشتیبان خصوصی برای بررسی چاپ می‌شود.

موفقیت نهایی با این پیام مشخص می‌شود:

```text
GATEWAY READY: https://api.khaanehyar.ir/ai-gateway
```

دو تحلیل نمونهٔ انتقال هزینه دارند؛ آزمون‌ها SMS واقعی نمی‌خوانند، تراکنش ثبت نمی‌کنند و
برای مدل‌های جایگزین درخواست پولی دیگری نمی‌فرستند.

## ارتقای دستیار خانه با حفظ تنظیمات موجود

این مسیر برای درگاهی است که قبلاً به DeepSeek منتقل شده است. بستهٔ جدید محلی آماده می‌شود؛
نصب روی سرور و انتشار برنامهٔ اصلی هرکدام اجازهٔ جدا می‌خواهند. لینک نصب انتقال قبلی، بستهٔ
ارتقای دستیار نیست و نباید برای این کار دوباره استفاده شود.

پس از تأیید نصب، نسخهٔ تازهٔ `vnc-installer.py` را با این گزینه اجرا کنید:

```sh
python3 /tmp/ai.py --upgrade-assistant
```

گزینهٔ ارتقا کلید DeepSeek یا رمز تازه نمی‌پرسد. فایل `.env` موجود با همان بایت‌ها، توضیحات
و پایان خط باقی می‌ماند؛ image تازه در فایل مدیریت‌شدهٔ `compose.yml` تعیین می‌شود. کلید
OpenRouter یا تنظیمات دستی دیگری که هنوز در فایل باشند نیز در این مسیر حذف نمی‌شوند.
نصب‌کننده همان قفل، ساخت جداگانه، بررسی پیش از جایگزینی، پشتیبان خصوصی و بازگردانی با image
قبلی را دارد. تنظیمات غیر DeepSeek، سرویس مدیریت‌نشده یا تغییر هم‌زمان مدیر، نصب را متوقف می‌کنند.

نسخهٔ زمینه‌آگاه، علاوه بر مسیر مستقل پیامک، چهار location دقیق دستیار دارد؛ مسیر عمومی
برای proxy دلخواه یا اجرای تغییرها افزوده نمی‌شود:

- `GET /ai-gateway/v1/assistant/capabilities`
- `POST /ai-gateway/v1/assistant/analyze`
- `POST /ai-gateway/v1/assistant/plan`
- `POST /ai-gateway/v1/assistant/report`

مسیر `analyze` برای سازگاری استخراج‌گر قبلی باقی مانده است؛ رابط تازه از `plan` و `report`
استفاده می‌کند. در بررسی HTTPS دستیار، درخواست بدون رمز باید ۴۰۱، قابلیت احرازشده باید
قرارداد نسخهٔ ۲ با `contextual=true` و `max_inferences=2`، و
ورودی نامعتبر احرازشده باید ۴۲۲ بدهد. این بررسی‌های دستیار تحلیل مدل انجام نمی‌دهند. دو تحلیل
نمونهٔ مالیِ جریان محافظت‌شدهٔ نصب همچنان هزینه‌دارند؛ بنابراین اجرای نصب یک بررسی رایگان نیست.
خطای مسیرهای تازه نیز کد، تنظیمات و image قبلی را بازمی‌گرداند؛ موفقیت پیامک به‌تنهایی کافی نیست.

درخواست کاربر دستیار خانه حداکثر ۸۰۰۰ نویسه و ۱۰ اقدام مستقیم دارد. هر ارسال حداکثر دو
inference دارد: شناخت درخواست و مرتب‌سازی نتیجه‌های مستند. آماده‌سازی تغییر، تأیید، اجرا و
استعلام رسید inference ندارند. مسیر پیامک و prompt قبلی مستقل می‌مانند. ظرفیت دقیقه‌ای و
هم‌زمانی میان مسیرهای تحلیل مشترک است؛ دریافت قابلیت‌ها inference نیست و هیچ سقف مالی یا
سهمیهٔ روزانهٔ تازه‌ای اضافه نشده است. درگاه قدیمی برای این رابط نیازمند ارتقاست؛ پیامک فعلی
نباید برای فعال‌کردن قابلیت تأییدنشده تغییر کند.

## اتصال محیط تست بعد از موفقیت سرور

در `configure-ai-test.bat` گزینهٔ «اتصال از طریق سرور خصوصی» را نگه دارید و نشانی بالا را
وارد کنید. کادر رمز خالی، رمز ذخیره‌شدهٔ فعلی را حفظ می‌کند. کلید DeepSeek را در این پنجره
برای حالت سرور وارد نکنید. با `npm run sandbox:refresh` محیط دستی روی پورت ۵۷۰۰ تازه می‌شود؛
دیتابیس و فایل‌های آن حفظ می‌شوند. تا موفقیت انتقال سرور، نسخهٔ دستی را برای این انتقال
فعال نکنید. بررسی واقعی باید فقط پیشنهاد تحلیل را باز کند، نه «ثبت» یا واردکردن تراکنش.

## نصب اولیه یا بررسی مستقل

سرور به Docker Compose، nginx، systemd و دسترسی به `api.deepseek.com` نیاز دارد.
تنظیمات در `backend/ai_gateway/.env` هستند: `DEEPSEEK_API_KEY`، `AI_GATEWAY_TOKEN` و
`AI_SMS_MODEL=deepseek-flash`. نمونهٔ بدون کلید در `.env.example` است.

نصب اولیه بدون گزینهٔ انتقال فقط پوشهٔ خالی را می‌پذیرد و تنظیمات خصوصی DeepSeek را در
ورودی مخفی می‌گیرد. ابزار بسته‌بندی با گزینهٔ اختیاری `--private-config` می‌تواند تنظیمات
خصوصی جدید را جدا بسازد؛ تنظیمات خصوصی موجود را هرگز بازنویسی نمی‌کند. این حالت برای
انتقال درگاه فعلی لازم نیست.

بررسی مستقل روی سرور نصب‌شده، از پوشهٔ `backend/ai_gateway`:

```sh
docker compose run --rm --no-deps -T gateway python -m ai_gateway.check
docker compose run --rm --no-deps -T gateway python -m ai_gateway.check --analyze
```

اولی فقط فهرست احراز‌شدهٔ مدل‌ها را بررسی می‌کند؛ دومی یک تحلیل ساختگی هزینه‌دار هم دارد.
هیچ‌کدام کلید یا پاسخ خام را چاپ نمی‌کنند. کانتینر با کاربر غیرریشه، فایل‌سیستم فقط‌خواندنی،
بدون قابلیت‌های اضافی و یک worker اجرا می‌شود. پورت و دیتابیس برنامهٔ اصلی تغییر نمی‌کنند.

## آزمون توسعه

```sh
python -m pytest ai_gateway/tests -q
```

آزمون‌های درگاه به دیتابیس و API واقعی نیاز ندارند. آزمون‌های
`tests/test_sms_assistant.py` باید با دیتابیس تست ایزوله اجرا شوند؛ از دیتابیس دستی استفاده
نکنید. پوشش متن‌های خطای برنامه با `npm run copy:studio:coverage` بررسی می‌شود.
