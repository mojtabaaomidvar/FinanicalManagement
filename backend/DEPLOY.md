# استقرار خانه‌یار روی لیارا — راهنمای گام‌به‌گام (فاز ۱۱)

راهنمای عملیِ بردنِ بک‌اند (FastAPI + PostgreSQL + فایل) روی لیارا، با دامنهٔ
`khaanehyar.ir`. این سند فقط **نامِ** متغیرها را می‌گوید؛ **هیچ مقدارِ محرمانه‌ای**
اینجا نوشته نمی‌شود — آن‌ها را فقط در پنلِ لیارا وارد کن.

نقشهٔ کلی:

- `api.khaanehyar.ir` → همین بک‌اند (اپِ `khaneyar-api`)
- `khaanehyar.ir` و `www` → وب‌اپِ PWA (جدا، هر جا میزبانی‌اش کنی)
- دیتابیس (`khaneyar-db`) و باکت (`khaneyar-files`) روی شبکهٔ خصوصیِ `khaanehyar`

فایل‌های آماده در این پوشه: `Dockerfile`، `.dockerignore`، `liara.json`.

---

## ۰) پیش‌نیازها (یک‌بار)

1. Node.js نصب باشد، سپس CLIِ لیارا:
   ```
   npm i -g @liara/cli
   liara login
   ```
2. سه سرویس از قبل ساخته شده‌اند (طبقِ راهنماییِ قبلی): دیتابیس `khaneyar-db`،
   اپ `khaneyar-api`، باکت `khaneyar-files` — همگی روی شبکهٔ `khaanehyar`.

> اگر شناسهٔ اپت با `khaneyar-api` فرق دارد، مقدارِ `app` در `liara.json` را عوض کن.

---

## ۱) متغیرهای محیطی (در پنلِ اپ → بخشِ «متغیرها»)

فقط نام‌ها؛ مقدارها را خودت وارد کن.

پایه:

- `APP_ENV` = `production`
- `DEBUG` = `false`
- `DATABASE_URL` = رشتهٔ اتصالِ Postgresِ لیارا، اما با دو شرط:
  1. پیشوند حتماً `postgresql+psycopg://` (نه `postgresql://` خالی)
  2. هاست، هاستِ **شبکهٔ خصوصی** باشد (نه عمومی)
  قالب: `postgresql+psycopg://USER:PASS@PRIVATE_HOST:5432/DBNAME`
- `CORS_ORIGINS` = `https://khaanehyar.ir,https://www.khaanehyar.ir`
  (با کاما، بدونِ فاصله، بدونِ `*`)

فایل‌ها (هر دو حالت لازم است):

- `FILE_SIGNING_SECRET` = یک رشتهٔ تصادفیِ قوی. بساز با:
  ```
  openssl rand -hex 32
  ```
  بدونِ این، آپلود و نمایشِ عکس‌ها کار **نمی‌کند**.
- `FILES_BASE_URL` = `https://api.khaanehyar.ir`
  (تا لینکِ عکس‌ها مطلق باشد و در `<img>` روی دامنهٔ PWA درست بارگذاری شود)

ذخیره‌سازیِ فایل — یکی از دو حالتِ بخشِ ۵ را انتخاب کن و متغیرهایش را اضافه کن.

پیامک (فعلاً خالی بگذار = حالتِ توسعه، بدونِ ارسالِ واقعی):

- `SMS_PROVIDER` ، `SMS_API_KEY` ، `SMS_SENDER`

> بقیهٔ تنظیمات (نشست، OTP، Argon2) پیش‌فرضِ امن دارند و لازم نیست ست شوند.

بازار (کاشیِ «ارز و بورس» — BrsApi) — روی VPS در `backend/deploy/.env`:

- `BRSAPI_KEY` = کلیدِ رایگان از `brsapi.ir/tsetmc-exchange-free-bourse-api-key-request/`
  (این سند مخصوصِ لیاراست؛ روی VPS همان متغیر را در `deploy/.env` سرور بگذار — `deploy/README-VPS.md`)
  بدونِ این، اندپوینتِ `/api/v1/market/prices` خطای SERVER_NOT_CONFIGURED می‌دهد.
- `MARKET_CACHE_SECONDS` = اختیاری، پیش‌فرض `300` (کشِ سرور-سمتی؛ سقفِ پلنِ رایگان
  ۱۵۰۰/۱۰۰۰ درخواست در روز است، با TTL پنج‌دقیقه‌ای خیلی زیرِ سقف می‌مانیم).

---

## ۲) استقرارِ کد

از داخلِ پوشهٔ `backend`:

```
liara deploy --app khaneyar-api
```

پلتفرم از روی `liara.json` روی `docker` و پورت `8000` تنظیم می‌شود. بیلد ممکن است
چند دقیقه طول بکشد.

> مهاجرت‌ها اینجا **اجرا نمی‌شوند** (عمداً) — بخشِ بعد.

---

## ۳) مهاجرت دیتابیس — ترتیبِ حیاتی (فاز ۱۰)

روی ۹ جدولِ داده، RLS به‌صورتِ FORCE فعال است؛ پس داده باید **پیش از** مهاجرتِ
`0002` بارگذاری شود. ترتیب مقدس است:

```
alembic upgrade 0001   →   بارگذاریِ داده   →   alembic upgrade head
```

چون منبع (Supabase) از داخلِ ایران معمولاً در دسترس نیست، **مطمئن‌ترین راه: از
کامپیوترِ خودت** که هم به Supabase و هم (به‌طورِ موقت) به دیتابیسِ لیارا دسترسی دارد.

1. در پنلِ دیتابیس، **دسترسیِ عمومی را موقتاً روشن کن** و رشتهٔ اتصالِ عمومی را بردار.
2. روی کامپیوترِ خودت، داخلِ `backend` (با محیطِ پایتونِ پروژه):
   ```
   export DATABASE_URL='postgresql+psycopg://USER:PASS@PUBLIC_HOST:PORT/DBNAME'
   alembic upgrade 0001
   ```
3. داده‌ها را بار بزن (منبع = Supabase، مقصد = همین `DATABASE_URL`):
   ```
   export SOURCE_DATABASE_URL='postgresql://…supabase…'
   python migration/migrate_essentials.py --dry-run   # اول آزمایشی
   python migration/migrate_essentials.py             # سپس واقعی
   ```
4. مهاجرتِ باقی‌مانده (RLS و…):
   ```
   alembic upgrade head
   ```
5. **دسترسیِ عمومیِ دیتابیس را دوباره خاموش کن.** (مهم)

> جزئیاتِ اسکریپت و پرچم‌ها (`--truncate` ، `--skip-reference`) در
> `migration/RUNBOOK.md`.
>
> جایگزین: فقط بخشِ `alembic` را می‌توان از «شلِ لیارا» (`liara shell --app
> khaneyar-api`) اجرا کرد چون فقط به دیتابیسِ خصوصی نیاز دارد؛ ولی بارگذاریِ داده
> به Supabase وصل می‌شود که از شلِ داخلِ ایران احتمالاً در دسترس نیست.

---

## ۴) دامنه و SSL

1. پنلِ اپ (`khaneyar-api`) → بخشِ **دامنه‌ها** → افزودنِ `api.khaanehyar.ir`.
2. لیارا یک رکوردِ DNS (معمولاً CNAME) نشان می‌دهد؛ آن را در مدیریتِ DNSِ دامنه ثبت کن.
3. پس از اعمالِ DNS، **SSLِ رایگان (Let's Encrypt)** را از همان صفحه فعال کن.

DNS برای کلِ دامنه (در پنلِ DNSِ لیارا یا رجیسترارِ `.ir`):

- `api` → طبقِ رکوردی که لیارا برای اپ می‌دهد.
- ریشه (`@`) و `www` → به میزبانِ وب‌اپِ PWA اشاره کنند (هر جا PWA را می‌گذاری).

## ۵) ذخیره‌سازیِ فایل — دو حالت

کد هر دو را پشتیبانی می‌کند؛ انتخاب فقط با **متغیرِ محیطی** است (بدونِ تغییرِ کد).

### حالت A — فضای آبجکتِ S3 (پیشنهادی؛ از باکتی که خریدی استفاده می‌کند)
اگر این چهار ست شوند، خودکار فعال می‌شود:

- `STORAGE_ENDPOINT` = آدرسِ endpointِ Object Storageِ لیارا
- `STORAGE_BUCKET` = `khaneyar-files`
- `STORAGE_ACCESS_KEY` ، `STORAGE_SECRET_KEY` = کلیدهای دسترسیِ باکت

فایل‌ها در باکت با کلیدهایی مثلِ `avatars/…` و `tx-photos/…` ذخیره می‌شوند. باکت
**خصوصی** می‌ماند؛ سرو کردن از راهِ URLِ امضاشدهٔ HMACِ خودِ اپ انجام می‌شود (نه لینکِ
مستقیمِ باکت). مزیت: مستقل از اپ، بدونِ دردسرِ دیسک، مقاوم در برابرِ استقرارِ دوباره.

### حالت B — دیسکِ ماندگارِ لیارا (بدونِ کد، سریع‌ترین)
اگر متغیرهای S3 را ست نکنی، اپ روی دیسکِ محلی (`STORAGE_DIR`، پیش‌فرض `./var/uploads`)
می‌نویسد. برای ماندگاری باید یک **Diskِ لیارا** روی همین مسیر mount کنی و مطمئن شوی
برای کاربرِ اپ قابلِ نوشتن است. باکتی که خریدی در این حالت بلااستفاده می‌ماند.

> پیشنهاد: حالت A. باکت را خریدی، معماری تمیزتر است و فایل‌ها به عمرِ کانتینر گره
> نمی‌خورند.

---

## ۶) فرانت (PWA/اندروید) — نکتهٔ بیلد

هنگامِ بیلدِ فرانت، این متغیر را ست کن (کد خودش `/api/v1` را می‌افزاید — پس **بدونِ**
`/api/v1` بنویس):

```
VITE_API_URL=https://api.khaanehyar.ir
```

سپس دوباره بیلد/دیپلوی کن تا اپ به بک‌اندِ جدید وصل شود.
